# iOS app rules

## Project facts
- Swift 6 language mode, `SWIFT_STRICT_CONCURRENCY = complete`, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, `SWIFT_APPROACHABLE_CONCURRENCY = YES`.
- iOS 26.2 minimum, iPhone and iPad. SwiftUI only (no UIKit unless wrapping).
- Build settings:
  - Put shared settings in `Shared.xcconfig` at the repo root. It is the base configuration for every project and target config.
  - `config/Shared.xcconfig` is an identical copy that nothing references.
  - Target-level settings in `project.pbxproj` (`SWIFT_VERSION`, `SWIFT_DEFAULT_ACTOR_ISOLATION`, `IPHONEOS_DEPLOYMENT_TARGET`, …) override the xcconfig. Changing one of those keys only in the xcconfig has no effect. Ask before moving them out of the pbxproj.
- Persistence: Core Data, not SwiftData.
  - `PersistenceController` (`Persistence.swift`) owns the `NSPersistentContainer` named `"hello"`, which must match `hello.xcdatamodeld`.
  - `PersistenceController.preview` is an in-memory store for `#Preview`s.
  - The `Item` NSManagedObject class is generated by Xcode (`codeGenerationType="class"`). Never write it by hand.
  - Changing the model needs a new model version so existing stores still load.
- Architecture target: MVVM with @Observable view models. The current code is the stock Xcode template: views use `@FetchRequest` and the environment `managedObjectContext` directly.
- Dependencies: Swift Package Manager only (no CocoaPods). There are none yet.
- Current layout: all sources sit directly in `hello/`, and there is no test target yet. The target layout for new code is `App/`, `Features/<Feature>/{Views,ViewModels,Models}`, `Core/`, `Tests/`.

## Swift 6 concurrency rules
- Code must compile with zero concurrency errors or warnings in Swift 6 mode.
- Everything is MainActor by default, so Views and view models need no annotation. Mark work that must leave the main actor `nonisolated` or move it into an actor.
- Types crossing actor/Task boundaries must be Sendable (prefer structs/enums; final class + immutable lets if needed).
- `NSManagedObject`s are not Sendable. Pass `NSManagedObjectID`s across boundaries, and do background work in `performBackgroundTask` or a background context.
- Use actors for shared mutable state (caches, stores, managers).
- Use async/await; no DispatchQueue or completion handlers in new code.
- Never silence errors with `@unchecked Sendable`, `nonisolated(unsafe)` or `@preconcurrency` without asking me first and adding a comment explaining why. That includes `@preconcurrency import` for old Apple or third-party APIs.
- Cancel long-running Tasks (store them; cancel in onDisappear/deinit), or use `.task { }` in SwiftUI, which cancels automatically.

## Never do
- Never hand-edit project.pbxproj. The `hello/` folder is a file-system-synchronized group, so any file added under it joins the target automatically.
- No force unwraps (!) or try! outside tests.
- No hardcoded strings in UI: use String Catalogs (Localizable.xcstrings).
- No secrets/API keys in source; use .xcconfig not committed to git.

## Swift style
- `SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY = YES`: each file must import every module whose members it uses.
- Use @Observable (Observation), not ObservableObject.
- Prefer value types (struct, enum); classes only when identity is needed.
- Every View has a #Preview. Split any body over ~50 lines into subviews.
- Use `NavigationStack`, not `NavigationView`.
- Accessibility: labels on icon-only buttons, support Dynamic Type.
- Tests use Swift Testing (`@Test`, `#expect`).

## Legacy template code
`ContentView.swift` and `Persistence.swift` break the rules above: force unwraps (`item.timestamp!`, `first!`), hardcoded strings, `NavigationView`, and `fatalError` in `catch` blocks. When you touch that code, fix it. Never copy those patterns.

## Verify before saying "done"
- Build: `xcodebuild -project hello.xcodeproj -scheme hello -destination 'platform=iOS Simulator,name=iPhone 17' build`
- Test: same command with `test` once a test target exists. Run one test with `-only-testing:<Target>/<Suite>/<test>`.
- Zero new warnings. Fix Swift 6 concurrency warnings, don't silence them.
